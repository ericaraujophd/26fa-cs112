One Class, One Type


typedef double Item;      // in PyList.h

PyList scores;            // holds doubles ✓
PyList names;             // also doubles ✗
Change the typedef and every PyList in the program changes with it. Want a PyList of doubles and a PyList of strings in one program? You'd need two copies of the class with different names.
Python never had this problem, a list holds anything. C++ needs types at compile time, so it needs another way.

A Class That Takes a Type


template <typename Item>
class PyList {
 public:
  void append(const Item &it);
 private:
  Item     *myArray;
  unsigned  mySize;
};

PyList<double>  scores;   // a PyList of doubles
PyList<string>  names;    // a PyList of strings
You instantiate a class to get an object. You instantiate a class template to get a class. PyList<double> and PyList<string> are two different, separately compiled classes.

Turning a Class Into a Template

  • Build and debug it first with typedef double Item;: get it working
  • Replace the typedef with template <typename Item> above the class
  • In the .cpp, put that same line above every method
  • Change each PyList:: to PyList<Item>::
  • Move the implementation into the header, then #include it

template <typename Item>
void PyList<Item>::append(const Item &it) { ... }
Debug once as a concrete class, then generalise. Templated compiler errors are famously unfriendly, don't meet them and your own bugs at the same time.
Talk to your neighbor · TTYN
Why does a class template's implementation go in the header?
  • A. Style, the committee preferred it that way
  • B. The compiler must see the code to generate a class for each type used
  • C. Headers compile faster than source files
  • D. So the linker can find it
✓ Answer
B. PyList<string> doesn't exist until someone writes it. The compiler generates the class on demand, which means the full body must be visible wherever it's used: so it lives in the header.

You Already Have One: vector


#include <vector>

vector<int> scores;

scores.push_back(90);       // append
scores.push_back(85);

cout << scores.size();      // 2
cout << scores[0];          // 90
The STL is a library of class templates: vector, list, stack, queue, set, map. You've just built a simplified vector: from here on you may use the real one.

What vector Gives You

Size and room

  • size() how many are in it
  • capacity() how many fit before it grows
  • empty() is it size 0
  • reserve(n) ask for room up front
  • resize(n) change the size itself

Reaching an element

  • v[i] no bounds check
  • at(i) checked, throws if out of range
  • front(), back() the ends

Adding and removing

  • push_back(x) our append
  • pop_back() drop the last
  • insert(pos, x) put one anywhere
  • erase(pos) take one out
  • clear() empty it

Positions

  • begin(), end() walk it forwards
  • rbegin(), rend() walk it backwards
Every one of these is something PyList either has or could have. The list is worth keeping: w3schools.com/cpp/cpp_ref_vector.asp

Iterators


vector<string>::iterator it;

for (it = names.begin(); it != names.end(); ++it) {
    cout << *it << endl;      // dereference, like a pointer
}
  • begin(): points at the first element
  • end(): points just past the last one
  • Every STL container is walked the same way
An iterator behaves like a pointer on purpose: *it to read, ++it to advance.

Walking a Vector

Counting the Work: Indexing


v[i]    →    *(myArray + i * sizeof(Item))
  • one multiply, one add, one dereference
  • three operations: whatever i is
  • whatever the size of the array is
Work that doesn't grow with n is constant time. Indexing an array is the classic example.

Counting the Work: Append

Room left


myArray[mySize] = it;   // 1 store
++mySize;               // 1 add

2 operations, whatever n is

Full


new Item[2 * n]   // room for 2n items
copy n items      // 3 ops each
delete [] old     // give it back
myArray = bigger  // repoint

3n + 5: three per item copied, plus five that do not depend on n (allocate, store, delete, repoint, count)

So which is it?

Amortized Constant Time

The Same Thing in Algebra

Suppose the array is full, holding n items. Take the next n appends:

  • The first one is the expensive one. Call its cost n.
  • The other n − 1 find room. Call each one 1.
totaln + (n − 1) × 1 = 2n − 1
per append(2n − 1) / n = 2 − 1/n
As n grows, 1/n shrinks and the average settles just under 2. It does not grow with n, and that is what amortized constant means.
Talk to your neighbor · TTYN
An earlier append grew the array by one slot each time it filled up. What did one append cost then?
  • A. Constant: it only adds one slot
  • B. Linear: every append copies the whole array
  • C. Amortized constant
  • D. It depends on the Item type
✓ Answer
B. Growing by one leaves the array full again, so the next append finds it full too. Every append allocates, copies all n items and frees. None of them is cheap, so there is nothing for the expensive ones to be spread across.
Talk to your neighbor · TTYN
Inserting at the front of a dynamic array is…
  • A. Constant time
  • B. Amortized constant time
  • C. Linear time, every element must shift up one
  • D. Faster than appending
✓ Answer
C. Every element already there moves one slot first, and the last one has to move first of all.

Week 05 Recap

  • A class template takes a type the way a function takes an argument
  • PyList<int> and PyList<string> are two separately generated classes
  • Template implementations live in the header
  • Every STL container is walked with begin() and end()
  • Indexing is constant; append is amortized constant; inserting at the front is linear
