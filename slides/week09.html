Abstract Data Type

An ADT is a promise: which operations you may call, what values it holds, what each one costs. Never how the data is stored.

The Stack is an ADT. An array or a linked list is a data structure: one way to keep the promise.

ADTs and How They Are Built

Python's list, dict and set from CS108 are three of these, built for you. One ADT, several data structures: choosing between them is what this course is about.

The Stack: Last In, First Out

s.push("blue");s.push("green");s.push("white");s.peekTop(); // "white", still theres.pop(); // "white"s.pop(); // "green"

Last in, first out: white went on last and comes off first. push, pop and peekTop all work at the top, and only there.

Whenever most recent first is the right answer, a stack is the right structure.

The Array Stack

s.push("a");s.push("b");s.push("c");s.pop(); // "c" stayss.push("d"); // over "c"

Nothing shifts: O(1). Full when mySize == myCapacity.

  • A. At the front, myFirst
  • B. At the back, myLast
  • C. It does not matter, both are equally fast
✓ Answer

A Stack Built on Your List


template <class Item>
class Stack {
public:
    void push(const Item& it) { myList.prepend(it); }
    Item pop()                { return myList.removeFirst(); }
    Item peekTop() const      { return myList.getFirst(); }
    bool isEmpty() const      { return myList.getSize() == 0; }
private:
    List<Item> myList;   // used only at its front
};
every method: one line already written and tested top = front: O(1) cost: a new per item

q.add("Ana");q.add("Ben");q.add("Cy");q.peekFirst(); // "Ana"q.peekLast(); // "Cy"q.remove(); // "Ana"q.remove(); // "Ben"

One Step Forward


++i;
if (i == myCapacity) {
    i = 0;

In one line, with no if?


i = (i + 1) % myCapacity;

0 → 1 → 2 → 3 → 4 → 0 → 1 → …

A Simple Hash Function


unsigned HashTable::hash(const string& word) const {
    return (word[0] + word[word.length() - 1]) % TABLE_SIZE;
}

How long does it take? O(1): two characters and a %, however many words are in the table.

contains

t.contains("Bob"); // truet.contains("Zoe"); // false

One hash, then one bucket. Never the rest of the table.

How Is contains O(1)?

It walks a bucket's list, and walking a list is O(n).

Yes. But what is n?

The length of one bucket, not the size of the table.

Enough buckets and a hash that spreads: n is about 1, so O(1). Everything in one bucket: O(n).

Your Turn: remove("Eve")

What are the steps?

  1. hash("Eve"): bucket 0
  2. take "Eve" out of that bucket's list

What does it cost?

Hash: O(1). Walk one bucket: about 1 long. So O(1), like contains.

A Good Hash Function

  1. Fast: O(1), it never looks at the table
  2. Spreads words evenly across the buckets
  3. Deterministic: the same word, the same bucket, every time

First + last character: fast and deterministic. Does it spread? You measure that in a11.

Too Many Collisions?

Load factor = words / buckets. Rule of thumb: 2 buckets per word.

1. More buckets
2. Probe
3. Hash again

Are 2 and 3 still O(1)?

On average, yes: with the load factor low, a free bucket is a step or two away. As the table fills, the search gets long, up to O(n). So real tables add buckets (1) before that happens.

Week 09 Recap

  • An ADT fixes the behavior and leaves the storage open
  • Stack = LIFO; Queue = FIFO; a hash table keeps no order at all
  • Put the action where the structure is fast: end of an array, front of a list
  • A naive array queue makes remove() O(n); a circular array fixes it
  • (i + 1) % myCapacity is the whole trick
  • myFirst starts at 0, myLast at capacity - 1; mySize tells full from empty
  • A hash table computes the index: one hash, one bucket, O(1) on average
