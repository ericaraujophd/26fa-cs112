Vector Subscript


v[i]    →    *(v.myArray + i * sizeof(Item))
3 operations, whatever i is and however big the vector is: constant time.

Vector Append

Room left


myArray[mySize] = it;
++mySize;

a few operations: constant

Full


new Item[2 * mySize]
copy n items
delete [] old

about 3n + 5: linear

Vector Append, on Average

Amortized constant time.

List Append


Node* n = new Node(it, nullptr);
if (mySize == 0) myFirst = n;
else             myLast->myNext = n;
myLast = n;
++mySize;
About 6 operations, empty list or not: constant.

List Prepend


myFirst = new Node(it, myFirst);
if (mySize == 0) myLast = myFirst;
++mySize;
About 5 operations, empty list or not: constant.

Vector Prepend

Every item shifts first: linear. So vector has no push_front.

List Subscript

About n/2 hops on average: linear. So STL's list has no [].

What O( f(n) ) Means

exact cost = a · f(n) + b

As n grows, f(n) dominates. Nobody cares about a and b.

At a Million Items

Reading It Off the Code


for (int i = 0; i < n; ++i) {
  total += a[i];
}

one loop over n: O(n)


for (int i = 0; i < n; ++i) {
  for (int j = 0; j < n; ++j) {
    if (a[i] == a[j]) ...
  }
}

a loop inside a loop: O(n²)

Loops one after another add, keep the biggest. Nested loops multiply.
Talk to your neighbor · TTYN
What is the complexity of this loop?

    cout << i << endl;

  • A. O(n)
  • B. O(n²)
  • C. O(lg n)
  • D. O(n lg n)
✓ Answer
C. O(lg n). i doubles each pass, so it reaches n after about lg n passes.

Searching a Million Items

SearchBig-OhComparisons
linear search, any vectorO(n)up to 1,000,000

Computers run on electricity. Fewer comparisons, less electricity, less carbon.
The source's slide 16. Search once: linear search is fine, sorting first (n lg n) costs more than it saves. Search many times: sort once, then binary search every time.

operator<<


ostream& operator<<(ostream &out, const List &list) {
    list.writeTo(out);
    return out;
}
out is not const: writing to it changes it.

Week 08 Recap

  • Big-Oh describes how work grows with n, not seconds on a clock
  • exact cost = a · f(n) + b; keep f(n)
  • Vector append is O(1*), amortized constant
  • Nested loops multiply; halving the problem gives lg n
  • Better algorithms use less electricity
